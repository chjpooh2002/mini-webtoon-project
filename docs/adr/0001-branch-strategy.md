# 0001. 브랜치 전략과 보호 규칙

- 상태: 채택
- 날짜: 2026-11-21
- 관련 이슈: #1

## 결정
- `main`(릴리즈)과 `develop`(통합) 두 브랜치를 둔다. 작업 브랜치(`<접두어>/#이슈번호-설명`)는 `develop`에서 분기해 `develop`으로 PR을 보내고, 릴리즈 때만 `develop` → `main`으로 병합한다.
- 두 브랜치 모두 PR 필수, 관리자 포함 적용, 강제 푸시·삭제 금지, 리뷰 대화 해결 필수.
- 필수 승인 수는 0으로 둔다.

## 이유
- 릴리즈 단위(v0.0.1 ~ v1.0.0)로 배포하므로 배포 기준 브랜치를 분리해 두면 6주차 태그 기반 자동 배포와 롤백이 단순해진다.
- 1인 개발이라 깃허브에서 자기 PR을 승인할 수 없다. 승인 1 이상이면 병합이 막힌다. PR 필수만으로도 "이슈 → 브랜치 → PR" 기록은 남는다.

## 나중에 바꿀 것
- CI 구성 후 상태 검사 통과를 필수 조건으로 추가한다.
